# 学期归档设计文档

## 一、设计概述

归档系统采用 **A表/B表** 架构设计：
- **A表（业务表）**：存储当前学期的活跃数据
- **B表（归档表）**：存储历史学期的归档数据

归档后，A表数据被清空，相当于全新数据库，所有历史数据可通过B表查询追溯。

---

## 二、数据模型

### 2.1 归档表结构

```python
class TermArchive(BaseModel):
    """学期归档表"""
    semester = models.ForeignKey('schedules.Semester', on_delete=models.CASCADE)
    archive_type = models.CharField(max_length=50)  # 归档类型
    content = models.JSONField()  # 归档内容（JSON格式）
```

### 2.2 归档类型 (archive_type)

| archive_type | 说明 | 数据来源 |
|--------------|------|----------|
| `usage_records` | 使用记录 | UsageRecord |
| `schedules` | 课表记录 | Schedule |
| `maintain_records` | 维护工单 | WorkOrder (maintenance_type != 3) |
| `fault_records` | 故障工单 | WorkOrder (maintenance_type == 3) |
| `lab_info` | 实训室信息 | Laboratory |
| `device_info` | 设备信息 | Equipment |

## 三、工单分类设计

### 3.1 WorkOrder 表

工单表通过 `maintenance_type` 字段区分类型：

| maintenance_type | 名称 | 编号前缀 | 归档类型 |
|------------------|------|----------|----------|
| 1 | 检查维护 | W | maintain_records |
| 2 | 安全检查 | W | maintain_records |
| 3 | 设备维修（故障） | G | fault_records |
| 4 | 升级改造 | W | maintain_records |

### 3.2 编号规则

```
维护工单: W + 日期 + 序号  例: W202604150001
故障工单: G + 日期 + 序号  例: G202604150001
```

## 四、删除实训室逻辑

### 4.1 设计原则

删除实训室时，**保留三个记录**（使用记录、维护工单、故障工单），确保历史数据可追溯。

### 4.2 处理流程

```
删除实训室
├── 课表 (Schedule) → 物理删除
├── 设备 (Equipment) → 物理删除
├── 使用记录 (UsageRecord) → 保留
│   └── 保存 laboratory_name, laboratory_code
│   └── 设置 laboratory = NULL
├── 工单 (WorkOrder) → 保留
│   └── 保存 laboratory_name, laboratory_code
│   └── 设置 laboratory = NULL
└── 实训室 (Laboratory) → 逻辑删除 (soft_delete)
```

### 4.3 记录模型字段

使用记录和工单模型新增字段，支持实训室删除后正常展示：

```python
class UsageRecord(BaseModel):
    laboratory = models.ForeignKey(
        'laboratories.Laboratory',
        on_delete=models.SET_NULL,  # 关键：设为NULL而非级联删除
        null=True,
        related_name='usage_records'
    )
    laboratory_name = models.CharField(max_length=100, blank=True, default='')  # 冗余存储
    laboratory_code = models.CharField(max_length=50, blank=True, default='')   # 冗余存储

class WorkOrder(BaseModel):
    laboratory = models.ForeignKey(
        'laboratories.Laboratory',
        on_delete=models.SET_NULL,
        null=True,
        related_name='work_orders'
    )
    laboratory_name = models.CharField(max_length=100, blank=True, default='')
    laboratory_code = models.CharField(max_length=50, blank=True, default='')
```

## 五、归档流程

### 5.1 归档步骤

```
1. 查询当前学期所有数据
   ├── 实训室列表 (lab_ids)
   ├── 使用记录
   ├── 课表
   ├── 工单
   ├── 设备
   └── 实训室信息

2. 复制数据到 TermArchive (B表)
   ├── 保存所有字段（包括关联ID和名称）
   └── 按 archive_type 分类存储

3. 删除业务表 (A表) 数据
   ├── records.delete()      # 使用记录
   ├── schedules.delete()    # 课表
   ├── workorders.delete()   # 工单
   └── labs.delete()         # 实训室

4. 结果：全新数据库
```

## 六、数据追溯设计

### 6.1 删除实训室后追溯

```
场景：实训室已删除，查看历史使用记录

查询使用记录：
├── laboratory = NULL（实训室已删除）
├── laboratory_name = "计算机实验室1"（保留）
└── laboratory_code = "LAB001"（保留）

展示：计算机实验室1 (LAB001) - 2026-04-15 数据结构实验
```

### 6.2 归档后追溯

```
场景：学期已归档，查看历史数据

查询 TermArchive：
├── semester_id = 2025-FALL
├── archive_type = "usage_records"
└── content = [所有使用记录JSON数据]

展示：从B表读取完整数据，包括关联信息
```

## 八、总结

| 操作 | 使用记录 | 维护工单 | 故障工单 | 课表 | 设备 | 实训室 |
|------|---------|---------|---------|------|------|--------|
| **删除实训室** | 保留 | 保留 | 保留 | 删除 | 删除 | 逻辑删除 |
| **归档学期** | 归档后删除A表 | 归档后删除A表 | 归档后删除A表 | 归档后删除A表 | 归档后删除A表 | 归档后删除A表 |

**设计目标**：
1. 删除实训室后，三个记录仍可正常查看和追溯
2. 归档后，B表保存完整数据副本，A表清空相当于全新数据库
3. 无论实训室是否被删除，归档数据都能正确追溯
