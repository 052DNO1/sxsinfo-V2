## 二、真缺口与落地方式（按性价比排序）

### 缺口 C：全局快捷键（最便宜、体验收益最直接）

**C1. 前端层（推荐先做，零依赖）** — 新建 `core/shell/useHotkeys.js`：

```js
import { onBeforeUnmount, onMounted } from 'vue'

/** 全局快捷键：Ctrl/Cmd+K 全局搜索、Ctrl/Cmd+R 只刷新当前表格 */
export function useHotkeys({ onSearch, onRefreshTable }) {
  function handler(event) {
    const mod = event.ctrlKey || event.metaKey
    if (!mod) return
    const key = event.key.toLowerCase()
    // 输入框里不抢 Ctrl+R，避免影响用户输入
    const tag = (event.target?.tagName || '').toLowerCase()
    const inField = tag === 'input' || tag === 'textarea' || event.target?.isContentEditable

    if (key === 'k') {
      event.preventDefault()
      onSearch?.()
    } else if (key === 'r' && !inField) {
      event.preventDefault()      // 关键：阻止 WebView 整页刷新
      onRefreshTable?.()
    }
  }
  onMounted(() => window.addEventListener('keydown', handler, true))
  onBeforeUnmount(() => window.removeEventListener('keydown', handler, true))
}
```

**C2. 与表格联动**：`DataTable.vue` 里把"刷新当前页"注册到 `statusStore`（与 `registerPaging` 同一模式），
全局快捷键调 `requestReload()`，只重发当前页请求，不刷新页面。

**C3. Rust 侧兜底（可选）**：`tauri::Builder::on_window_event` 里用 `WindowEvent::KeyboardInput`？Tauri 2 无该事件，
应改用 `tauri-plugin-global-shortcut`（真·全局，窗口失焦也生效）。若只在应用内生效，C1 足够。

### 缺口 B：原生右键菜单（Tauri 菜单 API）

现状 `ContextMenu.vue` 是 HTML 菜单，视觉可控、支持键盘；计划要求"原生"。两种做法：

```rust
// src-tauri/src/desktop_chrome.rs 追加：用 Tauri 的 Menu 作上下文菜单
#[tauri::command]
pub fn show_row_menu(app: AppHandle, window: WebviewWindow, row_id: String, x: f64, y: f64) {
    let menu = tauri::menu::MenuBuilder::new(&app)
        .item(&tauri::menu::MenuItem::with_id(&app, "edit", "编辑", true, None::<&str>).unwrap())
        .item(&tauri::menu::MenuItem::with_id(&app, "delete", "删除", true, None::<&str>).unwrap())
        .build().unwrap();
    window.popup_menu_at(&menu, tauri::LogicalPosition::new(x, y)).ok();
}
```
- 代价：原生菜单样式不跟随页面主题（与整体 UI 不完全统一），且需要 `core:menu:*` 权限；
- 建议：**保留 HTML 菜单为主、原生菜单作为可选项**（`localStorage.desktop_row_menu = 'native'` 切换），
  因为我们已经把 WebView 的默认右键菜单关掉了，当前体验是"应用自己的菜单"而非"浏览器菜单"。

### 缺口 A：Token 从 sessionStorage 迁到 `tauri-plugin-store`

```bash
# Rust
cargo add tauri-plugin-store
# 前端
yarn add @tauri-apps/plugin-store
```
```rust
// lib.rs
.plugin(tauri_plugin_store::Builder::default().build())
```
```js
// core/utils/tokenManager.js 改造要点：持久层可插拔
const store = await load('lims-auth.json', { autoSave: true })
await store.set('access', token)
```
注意两点：
1. **不要把 access token 只放 Rust 侧**——前端每次请求都要读它，跨进程读取会带来额外 IPC 开销；
   实际做法是"sessionStorage 缓存 + store 持久化"，冷启动时从 store 读回；
2. 需要 `capabilities/default.json` 放开 `store:default`。

### 缺口 D：TypeScript 迁移（属工程决策，不是补丁）

现状 200+ 个 `.js`/`.vue` 文件、无 `tsconfig`。可行路径：
1. 新增 `tsconfig.json` 允许 `allowJs`，先把 `core/api`、`core/store`、`core/hooks/base` **这三层**转 TS；
2. 用 `types/api.d.ts` 定义后端返回结构（`PageResult<T>`、`Term`、`Dept`…），页面层暂不转；
3. 好处集中在"请求层契约"上，迁移量可控（约 20 个文件）。**不建议一次性全量转**。

### 缺口 E：`plugin-http` 绕 CORS（可选）

只有当后端不方便配 CORS 时才需要。当前 axios 直连可用，说明后端已放行；
引入后请求走 Rust 进程，**反而失去**浏览器侧的 `AbortController`、cookie、部分调试便利。
**建议不做**，除非遇到 CORS 报错。

## 三、"部门管理"完整生命周期（现有链路的真实走法）

```text
views/pc/crud/list/DeptList.vue
  └─ useDeptList()                     core/hooks/domain/useDeptList.js
       └─ useBaseList()                core/hooks/base/useBaseList.js
            └─ BaseService             core/services/BaseService.js
                 └─ api (axios 实例)    core/api/client.js
                      ├─ 请求拦截：Authorization: Bearer <token>   (client.js:113)
                      ├─ 去重/排队：core/api/queue.js
                      └─ 响应拦截：401 → 刷新令牌重放 (client.js:164)
       └─ 返回 { columns, tableData, loading, error, totalCount, currentPage, pageSize, opt, ... }
  └─ CrudList.vue  →  DataTable.vue
       ├─ 请求中：v-loading（骨架/遮罩），工具条按钮禁用
       ├─ 完成后：publishTable({ label, page, pageSize, total, loaded }) → StatusBar「共 N 条数据」
       ├─ 行右键：ContextMenu.vue → emit('action-click', op, row) → handleActionClick（编辑/删除）
       └─ 删除成功：ElMessage 成功提示 + useCRUD 的 reload 回到当前页
```

**这条链已经完整闭环**，唯一"计划里有、链路里没有"的是：Ctrl+R 只刷新表格（缺口 C）与原生右键菜单（缺口 B）。

## 四、建议的执行顺序（每步都可独立验收）

| 顺序 | 事项 | 预计改动 | 风险 |
| --- | --- | --- | --- |
| 1 | 全局快捷键 Ctrl+K / Ctrl+R（只刷新表格） | 新增 1 个 hook + DataTable 注册刷新 | 低 |
| 2 | 网络失败 Toast + 状态栏联动复查（确认断网时不崩、提示统一） | `errorHandler` / `connection.js` 微调 | 低 |
| 3 | 分页/搜索参数与后端对齐复查（逐页核对 `page/page_size/search` 命名） | 各 domain hook 小改 | 中 |
| 4 | Token 迁移到 tauri-plugin-store（缓存 + 持久化两层） | Rust 插件 + tokenManager 改造 | 中 |
| 5 | 原生右键菜单（可切换，默认仍用 HTML 菜单） | Rust 命令 + 前端开关 | 中 |
| 6 | core 三层（api/store/hooks-base）转 TypeScript | ~20 个文件 | 中高 |

> 不建议做：重写 `core/api/client.js`、把 token 全量搬进 Rust、引入 `plugin-http` 替换 axios。
> 这三件事都会**降低**当前已经稳定的能力（令牌刷新、请求去重、调试可见性）。
