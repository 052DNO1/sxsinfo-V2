# 桌面端「套壳感」审计与改造方案

> 对象：`desktop/`（Tauri 2 + 系统 WebView2）
> 前端栈：**Vue 3.5 + Vite 7 + Element Plus 2.11（PC 端）+ Pinia 3 + vue-router 4(hash) + axios**
> 结论口径：**1–5 分**，5 分 = 与 VS Code / Linear / Raycast 这类原生桌面应用无异。
> 所有"证据"都来自本机实测（日志、Win32 查询、截图），不是推断。

## 一、套壳感审计（11 个维度）

| # | 维度 | 改造前 | 现在 | 关键证据 |
| --- | --- | --- | --- | --- |
| 1 | **窗口与标题栏** | 2 | **4** | 改造前：系统标题栏，窗口 1456×939（含 30px 标题栏）。现在：`decorations: false` + 自绘标题栏，外框 1456×909，**正好少掉标题栏**；仅剩 8px 缩放边框（保证仍可拖拽缩放）。Win11 圆角/描边由 DWM 补齐 |
| 2 | **菜单栏** | 2 | **4** | 改造前：经典 Win32 菜单条（文件/视图/帮助），是"网页套壳"最明显的外壳特征。现在：应用内菜单（标题栏内「菜单」按钮），复用同一套菜单 ID；日志：`自绘外壳模式：原生菜单栏已交由应用内菜单接管` |
| 3 | **导航** | 3 | **5** | 无地址栏、无标签页、无前进后退；`NavigationStarting` 白名单只放行 `tauri.localhost`，外部链接 `ShellExecuteW` 交给系统浏览器；`window.open`/`target=_blank` 直接取消 |
| 4 | **滚动** | 2 | **4** | 改造前：页面级滚动 + 浏览器默认滚动条。现在：`html,body{overflow:hidden}`，滚动交给应用内容器，`::-webkit-scrollbar` 8px 圆角细条；`overscroll-behavior:none` 去掉橡皮筋 |
| 5 | **右键** | 1 | **5** | `AreDefaultContextMenusEnabled=false`。实测：向 WebView 发送真实右键（WM_RBUTTONDOWN/UP）后，进程内 `#32768` 菜单窗口数 = **0** |
| 6 | **字体** | 3 | **4** | 现在强制系统字体栈（Segoe UI Variable / 微软雅黑 / PingFang SC …），`-webkit-font-smoothing: antialiased`；不再依赖 Web 字体渲染 |
| 7 | **动效** | 2 | **4** | 统一 `150/200ms` + `cubic-bezier(0.2,0,0,1)`；路由切换淡入淡出；启动占位淡出 200ms（占位已移出 `#app`，避免 mount 清空造成的白闪） |
| 8 | **快捷键** | 2 | **4** | `AreBrowserAcceleratorKeysEnabled=false`（F5/Ctrl+P/Ctrl+F/F12 等浏览器键全关；仍保留「视图→开发者工具」菜单入口）。**待办**：应用自己的快捷键体系（P1） |
| 9 | **系统集成** | 2 | **2** | 已有：单实例（命名互斥体+命名事件）、窗口状态持久化、任务栏身份（AppUserModelID）、服务器地址持久化。**缺**：托盘、系统通知、全局快捷键、文件拖拽（当前被导航白名单拦掉）、跳转列表 |
| 10 | **安装更新** | 3 | **3** | 已有：MSI/NSIS；两者**内建 WebView2 检测+静默安装**；「帮助→关于」显示版本/运行时/配置与日志位置。**缺**：自动更新、离线运行时模式（`offlineInstaller`）、安装选项 |
| 11 | **性能** | 3 | **3** | 安装包 6.64MB / exe 6.62MB；启动底色已改（无白闪）；**未测**：冷启动耗时、首屏 TTI；**缺**：骨架屏、启动耗时埋点、内存/CPU 观测 |

**总分：改造前 25/55 → 现在 42/55**（第 1–8 项已落地，9–11 是下一阶段）。

| P0-1 | 系统标题栏让外壳一眼是"窗口套网页" | 品牌自绘标题栏 | Rust：`decorations(false)`（`desktop_chrome.rs::CUSTOM_CHROME`）；`shell_window` 命令（minimize / toggle-maximize / toggle-fullscreen / close / start-drag）；DWM 圆角+描边。前端：`components/desktop/TitleBar.vue`（品牌标识 + 拖动区 + 应用内菜单 + 46×32 窗口按钮），`App.vue` 按 `isDesktop()` 挂载 | 窗口外框高度比改造前少 30px（实测 939→909）；标题栏可拖动、双击最大化、按钮图标随最大化状态切换 |

| P0-4 | 可选中文本、页面级滚动条 | 只允许输入区选中；滚动交给容器 | `desktop-shell.css`：`body{user-select:none}` + 输入区/表格/代码例外；`html,body{overflow:hidden}`；细滚动条 | 拖动页面不再选中文字；窗口右侧不再出现浏览器滚动条 |
| P0-5 | 启动白闪 | 无白屏、有过渡 | 控制器默认背景色 `#F0F2F5`；启动占位移出 `#app` 并在挂载后淡出 200ms；路由切换 200ms | 启动过程看不到白屏；路由切换无生硬跳变 |
| P0-6 | 字体与主题不像系统应用 | 系统字体栈 + 跟随系统暗色 | `desktop-shell.css` 字体栈 + 8pt 网格变量 + 明暗变量；`main.js` 引入 `element-plus/theme-chalk/dark/css-vars.css` 并按 `prefers-color-scheme` 切 `html.dark`；Rust 侧 `ThemeChanged` 推 `lims:theme` | 切换系统深浅色，界面（含 Element Plus 组件）跟随变化 |
| P0-7 | 连接守卫全屏浮层会盖住标题栏 | 让出标题栏 | `desktop-shell.css`：`.lims-shell > .connection-guard{ top: var(--lims-titlebar-height) !important }` | 后端不可达时仍能拖动/关闭窗口 |

> **回归风险的兜底**：`desktop_chrome.rs::CUSTOM_CHROME = false` 可一键退回"系统标题栏 + 原生菜单栏"。无边框窗口的缩放在 Win11 上仍可用（外框保留 8px 缩放边框）。

## 三、P1：近期（1–2 周）

| # | 问题 | 目标 | 实现 | 验收标准 |
| --- | --- | --- | --- | --- |
| P1-1 | 关窗即退出，常驻类使用不便 | 最小化到托盘 + 托盘菜单 | `tauri` 的 `tray-icon` feature（`TrayIconBuilder`，需确认 `tray-icon` 已在 cargo 缓存，否则先离线 vendor）；`WindowEvent::CloseRequested` 里改为 `hide()`；托盘菜单：显示主窗口 / 服务器设置 / 退出 | 关闭按钮 → 窗口隐藏、进程常驻；托盘双击 → 窗口恢复；托盘退出 → 进程结束 |

| P1-3 | 拖文件进窗口被白名单拦掉 | 拖拽导入 | 保留 `NavigationStarting` 白名单，但额外接 `tauri` 的 `DragDropEvent`（`WindowEvent::DragDrop`）→ 取路径 → 交给导入流程；WebView2 侧的 `AreDefaultContextMenusEnabled` 保持关闭 | 拖入 .xlsx → 直接进入导入预览；拖入无关文件 → 提示不支持，不跳转 |
| P1-4 | 快捷键体系缺失 | 应用内快捷键 + 菜单显示加速键 | 前端 `useHotkeys`（keydown 捕获，`CmdOrCtrl` 适配）；建议：`Ctrl+K` 全局搜索、`Ctrl+,` 设置、`Ctrl+Shift+I` 开发者工具、`F1` 关于；菜单项右侧显示快捷键文本 | 各快捷键生效且与菜单文案一致；输入框内不误触发（排除 input/textarea） |
| P1-5 | 首屏布局跳动、启动耗时未知 | 骨架屏 + 启动埋点 | 各主路由加骨架组件（Element Plus `el-skeleton`）；Rust 在 `WebView 已就绪` 时记时间戳，前端 `performance.now()` 上报首屏时间写进 `startup.log` | 首屏无布局跳动；日志出现 `首屏耗时=<ms>` |
| P1-6 | Win11 贴靠布局丢失 | 悬停最大化按钮显示贴靠面板 | 自绘外壳下由系统处理：保留窗口 WS_MAXIMIZEBOX 样式 + `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE)`；必要时用 `WM_NCHITTEST` 返回 `HTMAXBUTTON` 并在 `WM_NCMOUSELEAVE` 时发 `WM_SYSCOMMAND` | 鼠标悬停最大化按钮 → 出现 Win11 贴靠面板 |
| P1-7 | 环境标识不清 | 标题栏显示环境 | 标题栏右侧加"开发/测试/生产"胶囊标签，取自 `VITE_*` 或后端健康检查返回的环境字段 | 测试环境一眼可辨，避免误操作生产 |

## 五、参考的体验原则（借鉴，不复制）

| 来源 | 借鉴的原则 | 不照搬的部分 |
| --- | --- | --- |
| VS Code | 自绘标题栏 + 命令面板（Ctrl+K/Ctrl+P）；"标题栏即工具栏" | 它把菜单藏在汉堡里、快捷键极重；我们面向实训室管理员，菜单要显式可得 |
| Cursor / Trae | 环境标识（dev/prod）与版本信息放在关于里；升级提示用应用内 toast | 它们的 AI 面板/侧边栏与业务无关 |
| Linear | 动效克制（150–200ms）、快捷键优先、列表虚拟滚动 | 它的命令式导航（无菜单）不适合本系统的权限分层 |
| Raycast | 全局唤起（全局快捷键）、键盘可达 | 常驻托盘不是它的形态 |
| Notion 桌面版 | 更新提示"静默下载 + 下次启动生效"、离线优先 | 它的多窗口模型我们暂时不需要 |

## 七、VS Code 风格改造（2026-09-30 落地）

### 7.1 设计原则（借鉴来源，不照抄）

| 原则 | 出处 | 在本工程怎么落 |
| --- | --- | --- |
| 窗口只有上下两条细栏 | VS Code / Linear | 上：`TitleBar.vue`（Logo + 菜单 + 窗口按钮）、下：`StatusBar.vue`（用户 + 连接 + 条数 + 翻页），中间全是内容 |
| 层级靠分隔线，不靠阴影 | VS Code | `.el-card` 全局去边框去阴影去圆角；表格去外框；只用 1px 分隔线 |
| 高信息密度 | VS Code / Linear | 行高 28px、字号 12.5px、控件 26–28px、边距 8–12px、8pt 网格 |
| 悬停只用底色 | Linear | 去除位移/缩放类动效，保留 150ms 底色过渡 |
| 上下文操作用右键 | VS Code / 资源管理器 | `ContextMenu.vue`：贴边翻转、↑↓/Enter/Esc 键盘可达 |
| 状态信息常驻底部 | VS Code | 列表名/区间/已选/翻页/连接延迟全部下沉 |

### 7.3 为什么页面代码几乎不用改

`CrudList.vue` 把内容渲染进 `dashboard/Index.vue` 的 `#rightcontent`，而 `DataTable.vue` 承载了
工具条 + 表格 + 分页。因此这轮改造集中在 4 个文件：
`DataTable.vue`、`BaseLayout.vue`、`DashboardSidebar.vue`、`desktop-shell.css`，
外加两个新组件（`TitleBar.vue` 升级、`StatusBar.vue`、`ContextMenu.vue`）与一个状态单例
（`core/shell/statusStore.js`）。14 个列表页 **props/emits 全部保持不变**。

### 7.5 已知取舍

- **贴靠布局（Snap Layouts）**：悬停最大化按钮的 Win11 贴靠面板依赖系统标题栏命中区，
  自绘外壳下需要额外处理 `WM_NCHITTEST = HTMAXBUTTON`，列入 P1；
- **分页**：为保证 14 个列表页不改代码，翻页仍按页请求，只是入口从页面底部移到了状态栏；
  真正的"滚动即加载"（虚拟滚动）需要各页面改为追加模式，列入 P2；
- **行操作右键菜单**：行内没有可用操作时不弹空菜单（比"点了没反应"更清晰）；
  页面自定义 `row-actions` 插槽时保留一个 44px 的"更多"入口以兼容。

## 六、验收清单（可直接照着点）


1. 双击 `desktop\src-tauri\target\release\lims-desktop.exe` → **无白闪**，出现品牌自绘标题栏；
2. 拖动标题栏空白处 → 窗口跟随；双击 → 最大化/还原，按钮图标切换；
3. 点「菜单」→ 六项菜单与旧原生菜单一致，点「关于」看到版本/运行时/配置路径；
4. 在内容区右键 → **不出现**任何菜单；
5. 按 F5 / Ctrl+P / Ctrl+F → **无反应**；按 F12 或「菜单→开发者工具」→ 控制台可开（现场排障保留）；
6. 拖动选择页面文字 → 只有输入框/表格/代码块能选中；
7. 切系统深色模式 → 界面（含 Element Plus 组件）跟随；
8. 再双击一次 exe → 第二个实例不出现，已有窗口被提到前台（单实例内核对象）；
9. 停掉后端 → 连接守卫铺满内容区，**标题栏仍可操作**；
10. 关闭窗口再启动 → 位置/尺寸/最大化状态恢复。
